# Agent Note: NovaFlow 使用站点账号会话接入模型

Status: implemented

[English](2026-10-29-novaflow-site-session-login.md) | 中文

## 问题

选定的 New API 站点支持账号登录和模型调用，但没有实现继承的桌面授权扩展。要求用户创建并复制模型 API Key，会让桌面账号登录与模型使用脱节。

## 决策

NovaFlow 在启用 sandbox、非持久化的 Electron partition 中打开站点自己的登录页面。窗口仅允许同源导航，不提供 preload 或 Node 集成，并用可信窗口标题标识站点。页面负责站点既有的密码和附加验证；仅在登录成功后，原生代码才接收匹配的 HttpOnly 刷新 Cookie。

原生 broker 通过站点的刷新接口交换 Cookie。短期 dashboard 访问 Token 仅保留在内存中，刷新 grant 则经系统加密存储保存在独立账号目录。签发方绑定使取消和撤销操作的凭据仍发往原站点。关闭或取消登录会清理本次拥有的临时 partition；退出登录会停止本地请求准入并撤销站点会话。

账号发现取当前用户分组模型列表与站点明确声明支持 Chat Completions 的模型交集。既有私有桌面代理把该协议映射到账号鉴权的 `/pg/chat/completions` 接口，不创建模型或管理 API Key。初始模型尚未选择时采用第一个可用账号模型，已有的 API Key 模型选择保持不变。

## 考虑过的替代方案

自动创建模型 API Key 需要额外管理持久访问权限、额度和撤销。站点已有的会话网关能提供所需账号访问，因此不增加这份凭据。内嵌用户名密码表单会重复实现站点的密码加密与多因素流程，加载其自身的隔离页面能保留这些检查。系统浏览器登录无法在没有服务端回调扩展的情况下向应用交付 HttpOnly 刷新 Cookie。

## 后果

用户登录一次后，桌面端能在重启时恢复加密会话。账号会话支持流式 Chat Completions 和工具调用，Responses 与 Anthropic 接口继续通过可选的 API Key 提供方设置使用。账号额度仍以服务端为准；站点会话没有独立的设备预算，因此界面隐藏设备专属计量。旧桌面协议及其加密目录与标准站点会话实现保持独立。

针对性测试覆盖刷新凭据的持久化投影、签发方固定、账号范围内的模型发现、流式代理、重启、退出、取消以及隔离窗口清理。原生登录和模型调用使用所选站点自己的账号及余额，不使用应用共享凭据。
