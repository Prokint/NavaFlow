# Agent Note: NovaFlow 按认证身份隔离桌面工作区

Status: implemented

[English](2026-10-31-novaflow-account-workspaces.md) | 中文

## Problem

站点登录此前只改变模型访问权限，本机的工作区登记、会话历史和插件启用状态仍然共享。同一桌面端换人登录后，可能看到别人的会话，并运行别人配置的扩展。

## Decision

原生代码对精确的站点 origin 和服务器签发的用户 ID 计算哈希，选择桌面数据主目录和浏览器分区。准入下一账号前先停止旧 Host 和旧界面，并轮换私有请求代理的能力凭证。停止失败时，绝不让另一个账号使用旧进程。用户主动切换且存在运行中或已安排的任务时，需要先确认中断。

首次加密登录记录在刷新可能过期或替换它之前绑定旧数据。首次启动记录没有归属时，会永久阻止后续任意登录取得旧数据。凭证读取失败会停止初始化，不会将其写成无归属状态。旧账号的不可变会话文件、工作目录路径和浏览器分区保留原位。

新的已认证档案可以通过被动文件复制继承已安装的包内容，但只启用 base 和 Web bundle，不继承插件补丁或密钥。再次登录的档案保留各自选择。首次工作区的文件目录与登记存储均分别隔离。[账号参考](../../../../apps/desktop/novaflow/README.zh.md#account-workspaces)负责记录路径和操作行为。

## Alternatives considered

**按账号过滤侧边栏**仍然共享会话 API、凭证、已启用插件和后台进程。分别设置 Host 主目录，可让现有存储读取器使用同一身份，无需修改每个插件的持久化格式。

**将旧数据交给下一位登录者**可能把无法确认身份的旧用户数据交给别人。保留未分配的文件，在缺少可信登录记录时无法自动恢复，但不会猜测归属。

**共享原插件档案**会跨用户保留启用状态和密钥。重新执行包安装可能在新用户选择启用之前运行第三方脚本。被动复制包文件可以保留可用性，同时避免这两种行为。

## Consequences

切换需要重启 Host，新档案也会占用额外磁盘空间。应用账号隔离不会限制操作系统用户的文件访问权限。测试覆盖独立目录、被动继承且默认关闭的插件、旧数据绑定、迁移失败、代理准入、串行停止、被后续请求替代的切换，以及原生 A 到 B 再到 A 的窗口归属。登录界面未改变，因此现有账号界面快照仍然适用。
